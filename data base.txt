หมวดที่ 1: ข้อมูลตั้งต้น (Master Data & Configuration)
เก็บข้อมูลพื้นฐานของโรงเรียน เป็น "ตัวเลือก" ให้ผู้ใช้งานดึงไปใช้

1. academic_terms (ตารางปีการศึกษาและเทอม)
ใช้สำหรับแยกรอบการจัดตาราง ข้อมูลเทอมเก่าจะได้ไม่ปนกับเทอมใหม่

id (PK)

year (ปีการศึกษา เช่น 2569)

term (ภาคเรียน เช่น 1 หรือ 2)

is_active (สถานะเทอมปัจจุบัน: Boolean)

2. time_slots (ตารางโครงสร้างเวลาเรียน)
เก็บช่วงเวลาของแต่ละคาบ เพื่อให้ระบบใช้วาดช่องตาราง

id (PK)

day_of_week (วันในสัปดาห์: 1=จันทร์ - 5=ศุกร์)

period_number (คาบที่: 1, 2, 3...)

start_time (เวลาเริ่ม เช่น 08:30)

end_time (เวลาจบ เช่น 09:20)

3. teachers (ตารางบุคลากรครู)
เก็บแค่ข้อมูลพื้นฐาน (นำโควต้าคาบสอนสูงสุดออกตามที่ตกลงกันไว้)

id (PK)

full_name (ชื่อ-นามสกุล)

department (กลุ่มสาระการเรียนรู้)

4. classrooms (ตารางชั้นเรียน)

id (PK)

grade_level (ระดับชั้น เช่น ม.3)

room_name (ชื่อห้อง เช่น ม.3/1, ม.3/2)

lunch_period (รหัสคาบพักเที่ยงบังคับ เพื่อให้ระบบเว้นว่างให้อัตโนมัติ)

5. rooms (ตารางสถานที่/ห้องเรียน)

id (PK)

room_name (ชื่อห้อง เช่น ห้องคอมพิวเตอร์ 1, ลานกิจกรรม)

room_type (ประเภท: ห้องเรียนประจำ / ห้องปฏิบัติการเฉพาะ)

6. subjects (ตารางรายวิชา)

id (PK)

subject_code (รหัสวิชา เช่น ว23222)

subject_name (ชื่อวิชา เช่น วิทยาการคำนวณ)

หมวดที่ 2: การจัดการภาระงาน (Teaching Assignments)
นี่คือหัวใจหลักที่เปลี่ยนมาใช้ความสัมพันธ์แบบ Many-to-Many เพื่อแก้ปัญหาครูหลายคน/นักเรียนหลายห้อง

7. assignments (ตารางภาระงานหลัก)
เปรียบเสมือนใบสั่งงาน 1 ใบ ที่ระบุว่าวิชานี้ รูปแบบนี้ ต้องเรียนกี่คาบ

id (PK)

term_id (FK -> academic_terms.id)

subject_id (FK -> subjects.id)

room_id (FK -> rooms.id สามารถเป็น Null ได้ถ้าระบบสุ่มห้องให้)

total_periods (จำนวนคาบรวมต่อสัปดาห์ เช่น 2)

period_type (รูปแบบคาบ: 'single' คาบเดี่ยว, 'double' คาบคู่ติดกัน)

8. assignment_teachers (ตารางเชื่อมโยง ครู <-> ภาระงาน)
ไขกุญแจสำคัญของการ "สอนร่วม" (1 ภาระงาน ผูกครูได้หลายคน)

id (PK)

assignment_id (FK -> assignments.id)

teacher_id (FK -> teachers.id)

9. assignment_classrooms (ตารางเชื่อมโยง ชั้นเรียน <-> ภาระงาน)
ไขกุญแจสำคัญของการ "ควบรวมห้องเรียน" (1 ภาระงาน ผูกเด็กได้หลายห้องเรียน)

id (PK)

assignment_id (FK -> assignments.id)

classroom_id (FK -> classrooms.id)

หมวดที่ 3: เงื่อนไขและกิจกรรมล็อกเวลา (Constraints & Events)
ใช้สำหรับดักทางไม่ให้ระบบจัดตารางลงในคาบที่ครูไม่ว่าง หรือติดกิจกรรมส่วนรวม

10. fixed_events (ตารางกิจกรรมส่วนรวมของโรงเรียน)
จัดการกิจกรรมลูกเสือ ชุมนุม ประชุมวิชาการ ฯลฯ ที่บังคับคาบสอนไว้ตายตัว

id (PK)

term_id (FK -> academic_terms.id)

event_name (ชื่อกิจกรรม เช่น ประชุมวิชาการ, ลูกเสือ ม.1)

time_slot_id (FK -> time_slots.id ระบุวันและคาบที่จัดกิจกรรมอย่างชัดเจน)

room_id (FK -> rooms.id ถ้ามี)

11. event_participants (ตารางเชื่อมโยง ครู/ชั้นเรียน <-> กิจกรรม)
ระบุว่าใครบ้างต้องถูกล็อกตัวในกิจกรรมนี้

id (PK)

event_id (FK -> fixed_events.id)

participant_type (ประเภทผู้เข้าร่วม: 'teacher' หรือ 'classroom')

participant_id (รหัสของครู หรือ รหัสของชั้นเรียน ตามที่ระบุใน Type)

12. teacher_unavailabilities (ตารางล็อกคาบว่างส่วนตัวของครู)
เก็บข้อมูลคาบที่ครูแต่ละคน "ไม่สามารถสอนได้" (เช่น ติดงานพัสดุ งานธุรการ)

id (PK)

teacher_id (FK -> teachers.id)

time_slot_id (FK -> time_slots.id คาบที่ไม่ว่าง)

reason (เหตุผลเพื่อแสดงผล เช่น "งานวัดผล")
